资料页改头像这条路为什么也没存进库，没有查到直接证据。能确认的是旧实现把整张图片的 base64 存进用户表，之后每次返回联系人、群成员、消息都带着整张图，这本身就有问题，已经改掉。

## 3. 管理 API Key 与切换模型：支持多个服务商

### 原因

`provider` 这一个字段同时担了三个角色：渠道的唯一标识、服务商、接口协议（Python 按这个名字选适配器）。
数据库唯一键是（用户、provider、用途），界面新建时又直接用预设名当标识。
结果是：同一个服务商或"自定义"只能存一条，再加一条会把前一条的地址和密钥覆盖掉。库里现有数据正是一条 `openai` 加一条 `custom`。

### 修改

后端
- `model_credentials` 新增 `vendor`（服务商）和 `api_format`（接口协议）两列；`provider` 只保留唯一标识的作用。
- 保存时：带 `id` 就改那一条；不带就新增，标识重复时自动编号（`custom`、`custom-2`……）。新增不会再覆盖已有渠道。
- 新增 `ModelChannels`：统一决定发给 Python 的适配器名、哪些渠道可以不填密钥。Python 不需要改。
- 老数据（两列为空）按原来的方式解析，行为不变，下次保存时自动补齐。
- 每个用途最多 100 个渠道，只是防止无限增长的上限。
- 迁移脚本 `2026_11_23_model_channel_vendor_format.sql`；`ddl-auto=update` 也会自动加列。

前端
- 服务商目录扩到 21 个，分官方、聚合平台、本机、自定义四组，可搜索。预设只是地址模板，可以改。
- 自定义服务商可以选接口协议（OpenAI 兼容 / Anthropic / Gemini），可以添加任意多个。
- 管理弹窗：可搜索、显示总数、表格限高滚动、状态用中文；打开时不再逐个读取所有渠道的模型目录。
- 会话头部的切换模型改成可搜索的分组列表（新增 `ModelChannelSwitcher.vue`），支持键盘上下选择；不可用的渠道显示原因（未选择模型 / 缺少 API Key）。
- 陪伴角色的模型面板：渠道超过 5 个时出现搜索框，列表限高滚动。
- 用的都是项目已有的 Element Plus 组件（Popover、Select 分组、Table、Scrollbar、Radio），没有引入新的组件库。

### 验证

- 后端：同一账号连续保存 9 个渠道（含 3 个自定义、2 个 DeepSeek），各自保留自己的模型和密钥；按 id 编辑只改那一条；别的账号改不了；旧客户端的请求仍然可用。
- 把保存逻辑改回"按标识覆盖"，7 项测试失败。
- 真实页面里挂载组件：30 个渠道时切换器分 4 组、可滚动、搜索和键盘选择正常、不可用项点不动；管理弹窗 30 行不横向溢出；新增表单发出的内容与后端字段一致。

没验证的：没有用真实 API Key 保存或调用过任何服务商；各家的预设地址来自公开文档的记忆，没有逐个联网确认。
