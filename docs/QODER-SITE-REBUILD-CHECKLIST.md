## 5. 唯一生产后端地址

生产 Web 构建必须使用：

```env
VITE_API_BASE_URL=https://lvmacbook-air.tail007e54.ts.net/api
VITE_WS_URL=https://lvmacbook-air.tail007e54.ts.net/ws
```

- API 基址含 `/api`，业务调用不得拼成 `/api/api/...`。
- SockJS 基址是 **HTTPS `/ws`**，不是直接 WSS。底层 WebSocket 升级由 SockJS/后端处理。
- 二者同源、HTTPS、无凭据、无查询串；前端资源后端基址为同域名去掉 `/api`。
- 不使用旧 `47.118.29.122` 后端地址，不使用 Web 生产环境里的 localhost、127.0.0.1、私网 IP 或电脑内网端口。
- 不改成相对 `/api`、相对 `/ws`，不假设 Qoder 的静态站点会把它们代理到 Java。
- 不加入“Funnel 不通就退到旧 IP/本机”的生产回退。后端不可达就如实报错。
- 保留 DEV/Electron 已有本地行为；**不能为了产物达标去删除本地开发功能**。

Vite 的 `VITE_*` 值是**构建时注入**。站点发布后改本机文件、改部署服务的非构建环境或只刷新浏览器，都不能证明 bundle 地址变了。必须重新构建并检查实际已部署 JS。

## 9. 登录、资源、实时与流式契约不变

以现有 `src/services/runtimeConfig.js`、`src/services/api.js`、现有 WebSocket/agent 服务及 Java 入库契约为准，只读核对，不另写一套 API。

- 不伪造登录状态，不绕过401/403，不把 JWT/密码塞进 URL、源码、发布环境、截图或报告。
- 登录凭据只由用户本人输入；不要要求在聊天或文档里提供密码、登录令牌或其它秘密。

### 上传与资源

- 继续使用现有 FormData 上传接口及授权流程，不手写 multipart boundary。

- 保留 `blob:`/`data:` 和站点本身静态资源的合法行为，不把所有前端资源硬改成后端地址。

### SockJS/STOMP

- 使用第5节 HTTPS `/ws`；保留 CONNECT 鉴权、订阅、重连、退出/切账号清理。
- `/ws/info` 能返回只说明 SockJS 信息端点可达，不代表 STOMP 已鉴权、订阅或消息成功。浏览器必须从实际站点 Origin 检查 CORS/预检与升级；curl成功不等于浏览器已允许。
- 不删除实时连接，不用前端轮询或假消息替代 WebSocket。

### AI SSE

- 保留现有真实流式请求与事件解析、取消和错误处理。
- 既有 Java 流式入口为 `/api/agent/sessions/{id}/chat/stream`，完整方法与负载按已有服务，不凭本清单猜字段。
- 不把流式请求改成等待全量再显示，不用定时脚本模拟逐字回复。
- Python仅Java内部访问；前端不能直连8100、内置模型Key或调用私人模型服务代替后端。
- 没有 embedding 模型，不新增或尝试知识库上传/向量检索验收。

你可以先完成允许范围内的构建和发布准备。遇到404/502/503、连接拒绝、CORS/WS Origin 拒绝时：

1. 记录请求的方法、主机、路径、HTTP状态或浏览器错误；删除查询中的敏感内容和所有凭据。
2. 区分产物地址错误、静态资源/刷新问题与后端/网关尚未就绪。401/403及按隐私策略返回的404可能是正常业务拒绝，不是“网络断开”；保留真实状态，不改成成功。
3. 前端配置错误只能按第5/6节校准；后端、网关或新域名授权问题交本线程。
4. 如实标记“等待后端接通”，保留功能，不自动fallback、放宽Origin或添加mock。

不要让前端请求 `/internal/funnel/readiness`；该接口仅供本机/网关检查，公开网关不会放行。`/health`只表示网关存活，不是登录/AI验收。

## 12. 必须给出的验收证据

### A：前端准备/发布

后端未 ready 时，A 以构建、部署和非鉴权静态检查为完成条件。需登录或写入的请求检查标记“未执行—等待B”，不得为了完成A触发上传、发消息或其它业务写入；这些接口暂不可达不改变A/B分工。

- [ ] 使用现有仓库和 Web 构建，不是另一套生成项目。
- [ ] 现有前端测试与构建真实完成，记录结果；失败不删测试/功能绕过。
- [ ] 生产生效的 API/WS 基址分别为第5节两个值。
- [ ] **最终 Web JS 中旧IP与回环的后端端点数量为0**：`localhost:8080/api`、`localhost:8080/ws`、`127.0.0.1:8080/api`、`127.0.0.1:8080/ws`、旧47.118.29.122的 `/api`、`/ws`。检查限定为实际发布JS，不要求开发源码、文档、Electron配置里的所有localhost字样为0，不允许靠删除本地功能达标。
- [ ] 访问实际已部署页面并读取它引用的真实哈希JS，证明部署的是本次产物，不只检查本地dist。
- [ ] 非鉴权检查确认浏览器请求目标不退回旧IP/本机、无混合内容；需登录或写入的 API、SockJS 业务、上传资源操作留到B，后端未 ready 时标未执行，不冒充通过。
- [ ] 登录页、已有路由刷新、静态资源和现有移动断点可用；未检查项标明原因。
- [ ] 原网址保留；否则交付新Origin和待后端同步事项。
- [ ] 代码/配置diff没有越过第3节权限。

### B：后端就绪后的公网联调

以下必须是真实链路，未运行不能填“通过”。用户本人执行需要账号或写入的操作，或另行明确授权测试账号/非敏感测试数据。

- [ ] 从正式站点真实登录成功，失败登录如实返回；刷新后的登录/退出符合原机制。
- [ ] 聊天发送/接收与消息状态来自后端；没有假数据替代。
- [ ] 用户提供的非敏感文件上传、头像/附件显示与下载符合原权限契约。
- [ ] SockJS/STOMP鉴权、订阅、消息到达、断网恢复和退出清理实际验证。
- [ ] AI事件/文本分段实际到达；取消与错误状态真实处理，不用mock冒充。
- [ ] 匿名、跨账号/非成员及内部路径按已有后端策略拒绝；不擅自创建第二个账号/群组或改用户数据做测试。
- [ ] 至少一台未加入Tailscale的外部设备/手机移动网络可用。当前电脑curl成功不代替这一项。

每项填写“通过 / 失败 / 未执行”，并附非敏感证据。后端未就绪时允许A交付、B等待，**不允许声称全部完成**。

## 13. Qoder 最终报告格式

按下面顺序交付，不能只说“部署好了”：

1. 基线仓库/分支/SHA，当前发布提交或“无源码改动，仅重建发布”。
2. 开工前已有改动清单与你的新增改动清单，证明没有混入其他线程。
3. 修改文件列表、每个文件为何必要、最小diff；若有PR，给链接、changed_files与CI结果。
4. 实际构建目录、命令、Web模式、输出目录，以及两项公开地址。不得打印完整环境。
5. 实际站点URL/Origin，原站点是否保留、是否需要本线程同步新Origin。
6. 已部署HTML引用的入口JS/版本及端点检查证据；真实网络请求方法/主机/路径/状态，所有凭据和敏感查询脱敏。
7. 第12节逐项结果，明确A完成与B未完成/等待/失败的区别。
8. 剩余阻塞项、它们归前端还是后端线程负责、下一步所需条件；不能只写“网络问题”。
9. 回退位置/合规上一前端部署版本和方法，只处理自己新增的发布。**回退版本也必须满足第5节端点与安全要求**；旧版本含旧IP/回环后端时不得重新恢复上线，报告“无合规回退版本”。不停止后端、不重置Funnel、不删用户数据。保留原站点不等于授权重新发布其不合规旧产物。
10. 确认没有越界，并给git文件清单、产物公开范围等可核对依据；不要空口承诺。

## 14. 不允许的“捷径”示例

- “登录失败，我做个假登录先让界面能进。”——禁止。
- “后端没起来，我把API换成localhost或旧公网IP。”——禁止。
- “CORS拦了，我改后端allow-all或让前端跳过校验。”——禁止。
- “新站点换了域名，我直接改网关publicOrigin并开启Funnel。”——越界。
- “为Web打包方便，删掉Electron、本地逻辑、WS或附件权限。”——禁止。
- “反正是重建站点，我重写页面、store、模型请求。”——偏离。
- “看到登录页/health返回200，说明所有功能上线了。”——验收错误。
- “后端未就绪，所以我停止检查产物地址、只报一句无网络。”——不充分；仍应完成A范围的检查并列清B阻塞。
