# 公网登录与保存凭据安全契约

更新：2026-11-28。本文只描述功能和接口，不记录个人机器、账号或凭据信息。代码发布状态必须另行核对。

## 配置范围

以下开关默认关闭，只由隔离公网部署的 `public` profile 开启：

| 配置 | 作用 |
|---|---|
| `nexus.credentials.bound-to-address` | 已保存的模型 Key 与 MCP 凭据不能随改址发送给另一服务器 |
| `nexus.auth.single-session` | 每次完整登录成功创建新登录会话，提交后撤销旧会话并关闭旧实时连接 |
| `nexus.auth.two-factor-login-required` | 已启用二次验证的账号必须在发放 JWT 前完成第二因子 |

不新增登录冷却，不按成功登录次数限频。现有失败锁定和网关限流保留。未启用二次验证的账号不被强制注册验证器；本地默认的登录与多设备行为保持。

## 1. 保存凭据绑定服务器

服务器身份按协议、主机、有效端口比较，不按原始地址字符串比较。同服务器的路径更正不要求重填。

- 模型渠道已有 Key，换服务器却没有提交新 Key：保存返回参数错误，`details.reason=KEY_REQUIRED_FOR_NEW_ADDRESS`。
- 没有显式地址的渠道，按其适配器的缺省目标保守判断；无法证明是原服务器，不沿用旧 Key。供应商、API 格式的缺省目标切换与旧客户端请求形状也经过同一检查。
- MCP 服务已有凭据，换服务器却没有提交新凭据或明确清除旧凭据：保存返回 HTTP 400，`code=MCP_CREDENTIAL_REQUIRED`。
- 拒绝前不修改保存的地址、密文、版本、状态或授权；不把失败保存伪装成未配置 Key 的成功状态。
- 前端按固定错误标识显示对应语言的重填说明；编辑表单保留，凭据不回显。MCP 的错误归一化不能把这个错误吞成通用不可用。

## 2. 单会话与事务

账号数据库行锁统一串行化成功登录、改密和第二因子修改。锁定读取不能在等待锁前建立旧的可重复读快照。

1. 校验密码及适用的第二因子。
2. 每次创建新 sid，即使设备、浏览器、来源地址相同也不复用旧会话。
3. 在同一事务内删除旧会话、保存新会话并签发带 sid 的 JWT。
4. 提交后发送下线原因并真正关闭旧连接；事务回滚不发送撤销、不踢原设备。

普通请求和实时帧均检查 sid 的归属、有效期与唯一有效会话。签名仍然有效的旧 JWT 不等于仍被授权。公网新 JWT 还带有服务端签发、受签名保护的 `sessionPolicy=single-v1`；旧版本曾跨成功登录复用 sid，因此即使数据库只剩一行，旧版本 JWT 也不能在公网重连，必须重新完整登录。无 sid 或历史多会话同样失败关闭。本地默认关闭该校验，旧令牌兼容性不变，也不轮换签名密钥。

改密码与撤销其他设备保留发起请求 JWT 的真实 sid，不依赖设备页可变的 `isCurrent` 标志。旧请求在等待账号锁后也要重新核对当前授权，不能把过时的请求用于修改密码或关闭二次验证。

## 3. 实时连接

- 同一 WebSocket 传输不能通过再次 CONNECT 切换认证身份。
- 注册器保留真实的 native/SockJS 传输对象，单有 Redis 中的连接 ID 不算具备断连能力。
- 已撤销连接的入站 SEND/SUBSCRIBE/ACK 和出站业务帧均被拒绝，随后由服务端关闭。忽略客户端下线提示不能继续收发。
- 下线通知是服务器持有的私有标记，不接受客户端复制标记来绕过出站检查。
- Redis 撤销控制消息发往其他实例，即使当前实例也有连接；逐帧检查和定期清理处理过期令牌或丢失通知。
- 关闭码 `4001`，原因只允许 `new_login`、`password_changed`、`session_revoked`、`logout`。前端只据固定原因退出当前匹配会话；旧连接回调不能误退出新登录。

## 4. 第二因子登录

请求仍是 `POST /api/auth/login`：`usernameOrEmail`、`password`，另加可选 `twoFactorCode`。用户可以提交验证器的六位验证码，或一个未使用的恢复码。

| 响应中的 `messageKey`（`message` 可本地化） | 含义 |
|---|---|
| `error.auth.2fa.required` | 密码正确，但仍需第二因子；没有正式 JWT |
| `error.auth.2fa.invalid.code` | 验证码/恢复码无效 |
| `error.auth.2fa.code.used` | 这个 TOTP 时间步已经使用 |
| `error.auth.2fa.not.setup` | 已启用状态的配置不完整，失败关闭，不仅凭密码放行 |

- TOTP 记录最高已接受时间步，防止漂移窗口内重放。
- 恢复码只保存哈希。消费、创建新会话和 JWT 发行在同一事务；并发使用同一恢复码至多一次成功，发行失败时消费回滚。
- 缺码挑战不累计失败，也不清除既有失败计数；无效因子累计到已有失败保护。失败登录历史在原事务结束后独立保存，不丢失，也不在持锁时启动第二个写事务。
- 设置/确认流程仍保留。裸开关不能跳过确认；重复确认不能重新返回整套恢复码。
- 公网关闭已启用的二次验证时，`PUT /api/users/{userId}/security/two-factor` 在原 `{enabled:false}` 上接受可选 `code`，再次验证真实 TOTP 或恢复码；持有有效当前 JWT 不能单独关闭。验证和关闭同事务，回滚保留恢复码及启用状态。
- 敏感因子失败共享现有账号失败保护，缺码不计失败，验证成功也不清空此前登录失败；没有新增成功次数限制或冷却。本地默认不要求额外证明。
- 前端保留原确认框，只在后端固定缺码挑战后询问因子；取消、认证变化或非关闭确认的响应不显示关闭成功。敏感请求 DTO 不在调试字符串中暴露证明。
- 新字段 `UserSecuritySettings.lastAcceptedTotpStep` 可空。已有设置保持；部署按既有结构迁移策略增加列，不清空数据。

## 5. 前端与发布

现有登录页仅在真实后端挑战后显示第二因子输入；允许粘贴和密码管理器填充，错误有就近文本与焦点提示。验证前不保存凭据或假登录状态。

下线只清当前匹配的认证状态，不删除草稿、待发送消息或业务缓存。下线原因是一次性固定值，不存储 JWT 或任意服务器文本。

这次发布应先准备并发布包含第二因子输入的新前端，再备份并切换后端。旧前端面对已启用二次验证的账号会被正确拒绝，但没有输入验证码的位置；不得为了兼容旧页面放宽后端验证。

隔离单测/数据库回归不等于线上账号或真实网络验收。真实数据环境不运行会注册测试账号或清库的验收脚本。
