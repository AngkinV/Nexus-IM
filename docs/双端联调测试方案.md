# Nexus 双端联调测试方案（桌面端 + 网页端）

> 目标：在本机同时跑「Electron 桌面端」和「浏览器网页端」，用两个账号互相加好友、建群、发消息，验证实时推送。
> 文档基于 2026-11-22 实际跑通的环境写，端口/账号都是实测过的。

---

## 一、开第二个端口（核心问题）

### 结论

你原来的 `npm run dev` 已经占了 **5173**（Electron 桌面端）。
第二个窗口**不能用 5173**，因为 `vite.config.js` 里写了 `strictPort: true` —— 端口被占会直接报错退出，不会自动换端口。

### 推荐做法：第二个窗口开在 3000

3000 这个端口后端 CORS 已经白名单放行过（`SecurityConfig.java` + `WebSocketConfig` 都允许 `http://localhost:*`），**不用改任何后端代码**。

```bash
cd /Users/anglv/Nexus/nexus-chat-frontend

# 终端 1：桌面端（你已经在跑的）
npm run dev

# 终端 2：网页端
npm run dev:web -- --port 3000
```

然后浏览器打开 **http://localhost:3000** （用 `localhost` 不要用 `127.0.0.1`，原因见下面「坑」）。

### 为什么不用 5174

实测 `http://127.0.0.1:5174` 发预检请求会被后端 **403 Invalid CORS request** 拒掉，因为 5174 不在白名单里。
要用 5174 就得改 `nexus-chat-backend/src/main/resources/application.properties` 的 `cors.allowed-origins` 并重启后端。既然 3000 现成可用，没必要动后端。

### 已经帮你起好了

现在 3000 端口已经在跑（`vite --port 3000`），浏览器直接访问就行。要关掉：

```bash
lsof -nP -iTCP:3000 -sTCP:LISTEN     # 看 PID
kill <PID>
```

## 三、测试方案

### 阶段 0：环境自检（30 秒）

打开 http://localhost:3000 ，能出登录页就说明网页端 OK。
桌面端窗口如果已经在，直接下一步。

两端分别登录：
- 桌面端 → `alice01` / `（密码已脱敏，见本地记录）`
- 网页端 → `bob01` / `（密码已脱敏，见本地记录）`

**通过标准**：两端都进到主界面，左下角/头像处显示自己的昵称，好友列表能看到对方且显示**在线**。

---

### 阶段 1：在线状态 / WebSocket 连接

这是最容易出问题、也最值得先测的一环。

**操作**：两端登录后，看对方头像是否亮起（在线绿点）。

**通过标准**：
- alice 看到 bob 在线，bob 看到 alice 在线
- 关掉网页端标签页 → 桌面端里 bob 应在几秒内变灰（离线）
- 重新打开 → 又变回在线

**这一步挂了说明 WebSocket 没连上**，后面的实时消息一定不通，先解决它。

---

### 阶段 2：加好友

**操作**（用 A 端发起）：
1. alice 端点「添加好友 / 搜索用户」
2. 搜索 `bob01`
3. 发送好友请求，可带一句验证消息
4. bob 端应**实时弹出**好友请求通知（不刷新页面）
5. bob 点「接受」

**通过标准**：
- bob 端在**不刷新**的情况下收到请求通知
- 接受后，两端好友列表都出现对方，**都不需要手动刷新**
- 请求接受后 alice 端能收到「已成为好友」的推送

**补充测**：拒绝请求、删除好友、拉黑，各走一遍。

---

### 阶段 3：私聊发消息

**操作**：
1. alice 从好友列表点 bob，进入私聊
2. 发一条文本消息
3. 观察 bob 端

**通过标准**：
- alice 端消息立即显示（乐观渲染），随后打勾/变成「已送达」
- bob 端**不刷新**就收到新消息，会话列表出现红点未读数
- bob 点开会话 → 未读数清零，alice 端收到「已读」回执
- 双方消息顺序一致，时间戳正确

**多类型消息**：文本、表情、图片、文件、引用回复、撤回、编辑，逐项测。

---

### 阶段 4：建群 + 群消息

**操作**：
1. alice 端「创建群聊」，拉 bob 进群，起名
2. alice 在群里发消息
3. bob 端观察

**通过标准**：
- 建群后 bob 端**实时**出现新群（不刷新）
- bob 端能看到群成员列表、自己角色是 member、alice 是 owner
- 群消息两端实时同步
- bob 发群消息，alice 端也能实时收到
- 群里未读数正确累加/清零

**补充测**：拉第三个人进群、踢人、退群、转让群主、改群名。

---

### 阶段 5：边界与异常

| 场景 | 期望结果 |
|---|---|
| 网页端断网（DevTools → Network → Offline）再发消息 | 消息标红/发送失败，恢复网络后自动重连并补发 |
| 手动停掉 Java 后端，再操作 | 界面提示网络错误，不是白屏 |
| 一端退出登录，另一端看在线状态 | 变离线 |
| 同一个账号在两个窗口登录 | 看「会话管理」里是否出现两个设备（这个项目是按设备记录 session 的） |
| 消息里有 emoji / 长文本 / 换行 | 正常显示不乱码 |
| 快速连发 20 条 | 顺序正确，无丢失，无重复 |

## 四、出错看哪里（重点）

按「先看前端控制台，再看后端日志，最后看数据库」的顺序排查。

### 1. 前端报错 → 浏览器 DevTools

网页端：`F12` 或 `Cmd+Option+I`，看两个地方：

- **Console 面板**：JS 报错、`WebSocket connected` / `STOMP error` / `Message delivery failed` 都打在这里
  - 看到 `WebSocket connected` = 长连接建立成功
  - 看到 `STOMP error` = 认证失败或 token 失效
  - 看到 `No heartbeat response for 60s, forcing reconnect` = 心跳断了，网络或后端有问题
- **Network 面板**：所有 `/api/*` 请求
  - 点开失败请求 → **Response** 看后端返回的错误 JSON
  - 状态码速查：
    - `400` = 参数不对/业务校验失败（Response 里有中文原因）
    - `401` = token 过期或 session 被吊销 → 会被强制跳登录页
    - `403` = CORS 被拒 或 没权限
    - `500` = 后端代码异常，去后端日志看堆栈

**桌面端（Electron）**：窗口里按 `Cmd+Option+I` 打开 DevTools，和浏览器一样。
如果没有反应，在跑 `npm run dev` 的那个终端里能看到 Electron 主进程的日志（主进程的 `console.log` 打在终端，渲染进程的打在 DevTools）。

**关键**：Network 面板里如果 `/ws` 相关请求是红的/挂起，就是 WebSocket 层的问题，去看后端日志里有没有 `WebSocket JWT 认证成功`。

### 2. 后端报错 → 日志文件

后端在 `/Users/anglv/Nexus/nexus-chat-backend` 下跑，日志在 `logs/` 目录：

```bash
cd /Users/anglv/Nexus/nexus-chat-backend

# 实时跟踪所有日志（推荐，边操作边看）
tail -f logs/nexus-chat.log

# 只看错误
tail -f logs/nexus-chat-error.log

# 找某个时间段/某个关键词
grep "业务异常" logs/nexus-chat.log | tail -20
grep "发送消息失败" logs/nexus-chat.log | tail -20
grep "WebSocket" logs/nexus-chat.log | tail -20
```

日志里的关键行（都是真实会打的）：

| 日志内容 | 含义 |
|---|---|
| `业务异常: messageKey=...` | 业务校验没过，messageKey 就是错误码，能对应到界面提示 |
| `发送消息失败: ...` | 发消息链路异常，后面跟完整堆栈 |
| `WebSocket JWT 认证成功: userId=4` | 长连接认证通过 |
| `WebSocket 会话已被吊销, 拒绝连接` | token 对应的 session 被删了，需要重新登录 |
| `ERROR ... Exception` + 堆栈 | 后端 500 的根因，看最下面 `Caused by:` |

如果后端的启动终端还开着，控制台里也会实时打同样的内容（带颜色），比看文件方便。

### 3. 数据对不对 → 直接查库

```bash
cd /Users/anglv/Nexus/nexus-chat-backend
PW=$(grep -m1 'spring.datasource.password' src/main/resources/application-local.properties | cut -d= -f2-)
mysql -uroot -p"$PW" -D nexus_chat
```

常用检查：

```sql
-- 消息到底存进去没
select id, chat_id, sender_id, content, created_at from messages order by id desc limit 10;

-- 好友关系
select * from contacts order by id desc limit 10;

-- 好友请求状态
select id, from_user_id, to_user_id, status from contact_requests order by id desc limit 10;

-- 群和成员
select * from chat_groups;
select * from chat_members where chat_id = 3;

-- 在线状态
select id, username, is_online, last_seen from users;

-- 会话（设备）表
select id, user_id, device_name, is_current, last_active_at from user_sessions order by id desc limit 10;
```

**判断思路**：消息没到对端时，先查 `messages` 表 ——
- 表里**有**这条消息 → 写入成功，问题在 WebSocket 推送（看后端 `WebSocket` 日志 + 前端 Console）
- 表里**没有** → 写入就失败了，看后端 error 日志

### 4. 一个已知的排查障碍（实测发现的）

`POST /api/messages` 出错时，后端是这样返回的：

```java
catch (RuntimeException e) {
    log.error("发送消息失败: {}", e.getMessage());
    return ResponseEntity.badRequest().build();   // ← 空 body
}
```

也就是说**发消息失败时，Network 面板里只能看到一个 400 和空响应，看不到任何原因**。
这个接口的错误原因只打在后端日志里，所以遇到「消息发不出去」必须先看：

```bash
tail -20 /Users/anglv/Nexus/nexus-chat-backend/logs/nexus-chat-error.log | grep "发送消息失败"
```

（其它接口走 `GlobalExceptionHandler`，400 的 Response 里是有 `message` 和 `messageKey` 的，只有发消息这个接口是空 body。）

### 5. 报错反馈模板

发现 bug 时按这个格式记，定位会快很多：

```
【场景】网页端(bob) 收到桌面端(alice) 私聊消息
【操作】alice 发 "test 123"，bob 端页面停留不动
【期望】bob 端 1 秒内出现消息
【实际】10 秒后仍未出现，刷新后能看到
【前端】Console: 无报错；Network: /api/messages POST 200
【后端】logs/nexus-chat.log 里 01:49:32 有 "WebSocket JWT 认证成功: userId=5"，但之后没有推送日志
【数据】messages 表里有这条记录 id=18
【结论】消息写入正常，推送环节丢失 → 怀疑 WebSocketSessionRegistry 里 bob 的 session 注册失败
```

这个格式的关键是：**把「数据写没写进去」和「推送有没有发出来」分开**，一步就能砍掉一半排查范围。

## 五、几个容易踩的坑

1. **网页端要用 `localhost:3000`，不要用 `127.0.0.1:3000`**
   两者是不同的 Origin。虽然 `WebSocketConfig` 对 `127.0.0.1:*` 也放行，但保持 `localhost` 和后端 CORS 白名单完全一致，最省事。

2. **不要用 5173 开第二个窗口**
   `strictPort: true`，被占会直接崩，不会自动换端口。

3. **两端必须两个不同账号**
   共用后端和数据库，同账号登录会互相干扰在线状态和未读数。

4. **桌面端和网页端的 localStorage 是分开的**
   Electron 有自己的 userData 目录，浏览器有自己的。所以互不影响，可以各自记住登录态。

5. **改了 Python 后端（8100）的代码要重启才生效**，前端改了会热更新。

6. **后端 8080 不要自己重启**，那是你在管的。需要重启时我会提醒你。

## 附录：自己注册新账号

注册要邮箱验证码，本机开发环境是**真的发邮件**（QQ 邮箱 SMTP）。

省事的办法：直接读数据库里刚生成的验证码。

```bash
cd /Users/anglv/Nexus/nexus-chat-backend
PW=$(grep -m1 'spring.datasource.password' src/main/resources/application-local.properties | cut -d= -f2-)
mysql -uroot -p"$PW" -D nexus_chat -e \
  "select email, code, used from email_verification_codes order by id desc limit 3;"
```

界面上点「发送验证码」后，执行上面这条，拿最新的 6 位数字填进注册页就行。
验证码 10 分钟过期，同一邮箱 60 秒内不能重复发。
