# 任务规划

取代原来的 `IM_ENHANCEMENT_PLAN.md`，原计划的各期已并入下面的阶段。

## 定位

带 AI 助手的即时通讯。Java 后端是唯一数据源，Python Agent 只在内网，桌面端（Web 和 Electron）是唯一客户端。

## 范围

| 处理 | 模块 |
|---|---|
| 保留 | 聊天核心、用户鉴权、Agent、知识库 |
| 合并 | Companion 并入 Agent，作为一个人设 |
| 保留但默认关 | 3D 形象：用户在设置里打开后才加载资源 |
| 冻结 | 社区帖子、LangGraph 备选引擎、音视频通话（保留代码，不再投入） |
| 停止 | 手机端（`nexus-chat-app`）的全部开发 |

不换 Rust 重写后端。客户端内存先做按需加载，实测后再评估 Electron 换 Tauri。

## 阶段

- [x] 删除手机端部署脚本、未使用的配置、文件和依赖
- [x] 运行数据（上传文件、向量库）移出版本管理
- [x] Agent 测试与本机 `.env`、真实向量库隔离
- [x] 流水线配置（`.github/workflows/ci.yml`）
- [x] 身份统一从令牌取，接口不再信任请求里自报的 `userId`（`security/CurrentUser.java`）
- [x] 删除 WebSocket 的 `userId` 兼容分支，禁止订阅别人的频道
- [ ] 把上面两项在真实运行的服务上走一遍（目前只有单元测试，没有启动服务实测）
- [ ] 3D 模型和动作的上传、改名、删除：任何登录用户都能操作全局资源，需要加归属或管理员限制
- [ ] 文件下载和预览接口不需要登录，知道文件编号就能取
- [ ] 整聊已读（`markChatMessagesAsRead`）没有校验是否为聊天成员
- [ ] Java 给 Python 的内部令牌在配置里有写死的默认值
- [ ] `application.properties` 里写死的密钥改为环境变量，然后在流水线里加密钥扫描
- [ ] 轮换已经进过公开仓库的密钥（数据库、JWT、邮箱、内部令牌）
- [ ] 后端启动测试改用临时容器里的 MySQL 和 Redis，纳入流水线
- [ ] `main` 设为受保护分支

完成标准：改请求里的 `userId` 读不到别人的数据；三项自动检查在 GitHub 上全绿。

### M1 收敛范围

- [ ] 删除只有手机端使用的后端接口（社区帖子的去留随冻结决定、版本检查、`/ws-native` 及 nginx 反代）
- [ ] 决定 `nexus-chat-app` 目录是保留存档还是移出仓库
- [ ] Companion 并入 Agent，去掉 Java 里直连 LLM 的那套管线

- [ ] 引入数据库迁移工具，以 `schema_full.sql` 为基线，`ddl-auto` 改为只校验

完成标准：没开 3D 时不下载 Three.js 和模型文件；整套服务能用一条 compose 命令在本机起来。

### M2 消息可靠性

- [ ] 消息序号加数据库兜底，不再只依赖 Redis

- [ ] 发消息和同步主链路补测试

完成标准：清空 Redis 后序号不重复，离线消息不丢。

### M3 Agent 进对话

- [ ] 修复 `reply-publish`：走正常发送流程，带序号、实时推送和“AI 代写”标记

- [ ] 实测开关 3D 前后的内存，再评估 Tauri

完成标准：有实测的内存数据。
